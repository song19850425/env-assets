01这个仓库是做什么的

一句话：它是环境检测这个行当的「可操作版说明书」。 不是把标准、规程、案例抄一遍放到网上，而是把那些真正需要动手判断的环节， 做成能拖、能点、能看实时反馈的页面。

按「你要干什么」分，库里放三类东西：

你要干什么去哪个产品线里面是什么
我要学会怎么做EnvLab 89 件交互式实验与仪器操作培训，在浏览器里走一遍完整流程
我要把活干完EnvWork 21 件工具、速查表、作业规范、脱敏案例与文档结构模板
我要查标准EnvStandard 24 份标准的结构化索引：333 项检测因子、466 项规定参数，逐条带出处
我要看数据EnvData 豫北四市空气质量日报 / 周报 / 月报，流水线每小时自动生成

注意 EnvData 与另外三条不同：那 110 件是手工做的资产， 大气管家是自动流水线的产物，所以不并进「件数」里，单独标注「自动更新」。

02为什么要开这个仓库

起点：那些「看一眼就懂、说不清」的东西

干了十几年环境检测和环保咨询，最常遇到的一类知识是这样的 —— 滴定终点什么时候到、空白为什么会漂、穿透曲线哪个点开始拐、 风量虚标在现场长什么样。老师傅看一眼就知道，但要说清楚， 得配着手势讲半小时，讲完对方还是一脸茫然。

问题在于载体不对。这类知识写在纸上永远是死的：文字描述不了「手感」， 照片拍不出「过程」，视频只能看不能操作。而它本来就是一个 「调一下参数 → 看结果怎么变」的东西 —— 那它就该是个能操作的网页。

于是有四件具体的事想解决

① 带教成本太高

同一个实验，新人来一批就要从头讲一遍。做成能自己点、自己试错的页面，重复劳动才降得下来。

② 经验留不住

会的人走了，判断标准也跟着走。写进页面的参数、判据和流程，才算是留在了机构里。

③ 标准数字抄来抄去

行业里到处是转手好几遍的限值和条款号。差一位数，结论就反过来 —— 而没人能说清它是从哪抄的。

④ 演示工具本身不靠谱

很多演示页要装环境、要连 CDN、要联网。到了现场、教室或断网的机房里，直接用不了。

所以定下了三条底线

单文件、零外部依赖、断网可用。 每件资产都是一个 HTML 文件，不引 CDN、不引外部字体、不需要构建步骤。 拷到 U 盘里、发给学员、扔进内网，都能直接打开。
标准引用必须能溯源。 页面上出现的法规数值都要标出标准号与条款/表格位置；EnvStandard 进一步把标准做成 结构化数据，让「标准 → 方法 → 实验 → 仪器 → SOP → 报告」这条链可以逐段追溯。
案例与企业信息全部脱敏。 库里的真实案例来自实际项目，但企业名称、人员、地名均已处理， 只保留「这个坑是怎么踩的」这部分价值。
它不是法定检测报告，也不替代有资质的第三方检测机构。 这里的东西是教学与工作辅助用的：可以拿来练手、对着干活、核对标准出处， 但正式出具结论、判定达标与否，仍要按现行标准和资质要求走。

03项目大纲：第三方检测实验室的主体构架

这个库不是按「文件类型」堆起来的，而是按一家能对外出报告的第三方环境检测实验室 实际怎么运转组织的。下面把实验室的主体构架拆成 A / B / C 三层、共 11 个环节， 每个环节标出库里对应哪些资产、覆盖到什么程度。

覆盖度是如实标注的：已覆盖 部分覆盖 —— 没做到的地方会直接写出来，不装作做完了。

LAYER A实验室能开张的前提· 3 个环节
A01资质认定与质量体系已覆盖

CMA 资质认定、CNAS 认可、内审与管理评审、不符合工作控制 —— 决定这家实验室能不能对外出报告、报告有没有法律效力。

▸CMA 现场核查总表（2023 版）
▸CNAS-CL01 现场核查总表
▸CMA 与 CNAS 双体系对照表
▸角色化核查清单（按岗位分）

现场核查维度已覆盖；体系文件的编制与内审记录留白。

A02合同评审与业务受理部分覆盖

客户委托进来先做合同评审：检测项目、依据标准、点位与频次、时限、费用，以及要不要分包。CMA 要求这一步留痕，不能口头答应。

▸第三方检测机构合规管理 · 操作规范
▸企业环保合规全栈服务目录

有服务目录与合规规范；委托单、合同评审记录这类表单还没做成页。

A03人员、设备与设施部分覆盖

谁能上机、谁能签字要授权；设备要检定校准、期间核查；环境条件要监控 —— 人、机、料、法、环五项里最容易在评审现场被挑的三项。

▸仪器操作规程页（6 台，逐步走查）
▸仪器分析交互页（35 台，含参数与谱图）

仪器侧做得很厚；人员授权表、设备台账与期间核查记录还没有对应页面。

LAYER B一份样品的完整旅程· 6 个环节
B01监测方案设计已覆盖

踏勘之后定：测哪些因子、按哪个标准、布几个点、采几次、什么时段采。方案定错，后面采得再规范也是白做。

▸监测方案智能生成器（多类型版）
▸检测因子实验室交互方案

按土壤 / 地下水 / 废水 / 废气 / 噪声场景生成方案。

B02现场采样与样品运输已覆盖

布点、采样操作、现场记录、样品保存与运输 —— 检测结果的上限在这一步就定死了，实验室再准也救不回一个采错的样。

▸固定源废气采样
▸土壤采样布点
▸地下水洗井 + 采样
▸地表水采样布点
▸环境空气 PM2.5 采样
▸采样字段模板（水/气/土/噪声）
▸水和废水采样填表向导

水、气、土、地下水四类介质都有可操作页面；噪声采样尚无对应页。

B03样品接收与流转部分覆盖

接样验收（容器对不对、保存剂加没加、温度合不合规）、编号、储存、流转、留样与处置。样品一乱，后面所有数据都失去可追溯性。

▸检测因子实验室交互方案 · 接样验收流程
▸实验分组任务单（可下发各实验组）

有接样验收流程与分组任务单；样品编号规则、留样台账还是空白。

B04前处理与仪器分析已覆盖

消解、萃取、吹扫捕集、浓缩定容，再上机：AAS / ICP-MS / ICP-OES / GC-MS / LC-MS / HPLC / 离子色谱 / 分光光度……这是实验室投入最重的一段。

▸检测实验（12 个完整流程）
▸仪器分析交互页（35 台）
▸仪器培训规程（6 台，逐步走查）
▸气相色谱方法开发速查表

库里最厚的一段：从样品到结果的操作序列都能点。

B05质量控制部分覆盖

空白、平行样、加标回收、标准曲线、质控样、能力验证、期间核查 —— 质控不是「补一个流程」，它是报告能不能签字的判据。

▸质量控制训练室（四关训练：平行样 / 空白 / 校准 / 异常处置）
▸检测实验页内的质控环节（空白/平行/加标）
▸检测因子实验室交互方案 · 质控审核段
▸CMA 现场核查总表 · 质控条目

已有独立的质控判读与异常处置训练（判据逐条带标准出处）；能力验证、期间核查、质控图仍是空白，加标回收率限值与相关系数 r 因标准未给统一规定，模块内明确标为「无统一阈值」而不编造。

B06数据处理与报告部分覆盖

计算、修约、三级审核、报告编制、签发与归档。数字算对了但报告写错，前面的功夫一样归零。

▸COD 检测实验 · 从水样到报告
▸检测因子实验室交互方案 · 报告出口

有一条从样品走到报告的完整样例；报告模板与审核流尚未成页。

LAYER C依据与延伸· 2 个环节
C01标准与方法依据已覆盖

限值、方法、检出限、采样要求都来自标准。数字抄错一位，结论就可能反过来 —— 所以这一层的关键不是「收录多少」，而是每一条能不能追到出处。

▸EnvStandard 标准库（24 份标准）

333 项检测因子 + 466 项规定参数，逐条带标准号与条款/表格位置。

C02区域数据服务（延伸）已覆盖

不针对单个委托，而是持续看一个区域的空气质量 —— 由流水线自动跑，把「数据获取」这件事本身自动化。

▸大气管家 · 豫北四市日报/周报/月报

数据源为中国环境监测总站实时发布平台，每小时自动更新。

06怎么用

只想看看

打开在线地址，首页有搜索框和分类筛选，按关键词或分区点进去。

拿去上课

整个文件夹拷给老师或学员，断网也能跑，不用装任何环境。

发在线地址即可；单个实验页的地址也能单独分享给某个人。

07数据与边界

  • 脱敏：库内案例、企业名称、人员信息、地名均已脱敏处理。
  • 标准：条文与数值引用均标注出处；实际使用请以国家 / 地方发布的现行有效版本为准。
  • 大气数据：数据源为中国环境监测总站实时发布平台；页面由自动化流水线生成，未经人工审定，仅供技术交流参考，不作为行政决策或处罚依据。
  • 合成数据：少数演示页为教学目的使用构造数据，页面上会明确标注。
  • 结论：本库内容不构成法定检测报告，不替代具备资质的第三方检测机构出具的结果。
